## 今日要点

1. **人类在环正在从一个兜底按钮变成产品的默认边界。**Fan 将登录、验证码、敏感字段和支付/发送/删除等后果性动作列为应暂停或交接的节点。
2. **可复用的 Agent 改进对象不只是模型。**AutoDesign 提出以完整轨迹与反馈来更新 Harness 的部件；其代码、评测协议和编辑产物均已公开，便于复查其主张的实现路径。
3. **长链路执行需要“何时提交”的语义。**ACID-Agent 的实现把候选结果、证据审查与弱证据下的重试拆开；这不能自动保证正确，却把失败和审查位置显式化。

## 开源项目

### Fan Browser Agent：在可见浏览器里运行，并把关键动作交还给人

![Fan 的官方仓库图标](https://raw.githubusercontent.com/7757/Fan-Browser-Agent/main/apps/desktop/assets/icon.png)

*图：Fan 官方仓库中的应用图标；原始来源：[7757/Fan-Browser-Agent](https://github.com/7757/Fan-Browser-Agent)。图片无法加载时，请以仓库 README 为准。*

- **首次公开：**GitHub API 显示仓库创建于 **2026-08-14 01:54 UTC**，许可证为 MIT。
- **项目：**[7757/Fan-Browser-Agent](https://github.com/7757/Fan-Browser-Agent)。
- **项目自述：**这是由 Electron、嵌入式 Chromium 与本地 Python 运行时组成的桌面 Agent；模型通过精简的浏览器接口观察与执行，用户可在同一工作区查看页面、标签、进度和待确认操作。README 明确称其为 early preview。
- **为什么值得关注：**它把“浏览器自动化”的安全边界写进交互：登录、验证码、敏感输入及提交、付款、消息、删除等操作会暂停并由用户接管，而不是默默跨过。这为需要真实网页操作的 Agent 提供了一个可检查、可干预的产品模式。
- **采用提示：**作者也提醒该程序可调用终端、读写本地文件，并会用到操作系统权限；可见界面不是沙箱。初次使用应从低风险、可验证的任务开始，审查模型供应商、MCP/插件与本地凭据边界。

### AutoDesign：把改进焦点放在 Design Harness，而非模型权重

![AutoDesign 的官方 README 研究产品主视觉](https://raw.githubusercontent.com/Yaxin9Luo/AutoDesign/main/assets/readme/hero-research-product.webp)

*图：AutoDesign 官方 README 的研究产品主视觉；原始来源：[Yaxin9Luo/AutoDesign](https://github.com/Yaxin9Luo/AutoDesign)。图片无法加载时，请以仓库文字和技术报告为准。*

- **首次公开：**GitHub API 显示仓库创建于 **2026-08-14 02:38 UTC**；仓库未声明可识别的 SPDX 许可证，使用前应先向维护者核实授权范围。
- **项目：**[Yaxin9Luo/AutoDesign](https://github.com/Yaxin9Luo/AutoDesign)。
- **项目自述：**项目围绕论文到可编辑海报的长程生成：内环生成和修改单个成品，外环根据 rollout、评估、单组件更新提案和接受门来改进 Harness。README 描述其覆盖上下文/记忆、工具/规范、运行时、编排及评估反馈五类部件，并公开了海报、幻灯片、网页和视频示例。
- **为什么值得关注：**它把 Agent 的“学习”落到可见的系统部件与执行轨迹上，而非笼统宣称模型更强。对搭建 Agent 工作流的团队而言，固定模型配合可版本化的提示、工具、验证器和编排策略，通常比一次性调参更容易复现、比较与回退。
- **解读边界：**README 所列分数与成本由项目方报告；海报之外的幻灯片、网页和视频仍是 pilot，作者明确表示尚需各自的评测与验证门。因此不应把该仓库的海报评测外推为所有设计生成任务的能力结论。

### ACID-Agent：用事务式提交约束数据科学 Agent 的执行链

- **首次公开：**GitHub API 显示仓库创建于 **2026-08-14 01:50 UTC**，许可证为 Apache-2.0。
- **项目：**[TsinghuaDatabaseGroup/ACID-Agent](https://github.com/TsinghuaDatabaseGroup/ACID-Agent)。
- **项目自述：**仓库将每一步视为“agentic transaction”：探索候选、检查证据、在证据较弱时重试，并在审查通过后提交。代码附带 KramaBench 集成、Claude Code/Codex 风格基线封装、轨迹及 token/运行时/代码执行次数记录。
- **为什么值得关注：**事务语义提供了一个有用的工程提问：这一步的证据是什么、失败时保留什么、满足何种条件才将结果视为可提交？这比把多步 Agent 任务当成一次不可见的黑箱调用更利于调试和审计。
- **采用提示：**复现实验需要 Docker、另行准备的数据集和本地评分模型；仓库也说明 API 成本会随供应商变化。因此当前材料足以复现其工作流，不足以独立证明跨场景的可靠性或经济性。

### AutoDesign 技术报告：用元 Harness 优化处理长程设计生成

- **公开时间：**[arXiv:2608.13560](https://arxiv.org/abs/2608.13560) 的 v1 时间为 **2026-08-13 17:59 UTC**，并非 8 月 14 日新投稿；本期收录原因是其对应开源实现于今日公开。
- **研究内容：**作者将论文到海报视作长程 agentic 过程，提出以元优化器根据 rollout 反馈迭代 DesignHarness，并给出涵盖五个学科、100 篇论文的 PosterBench，以及固定 10 篇论文的受控子集。
- **作者报告的结果：**技术报告称，在其 Main Track 上 AutoDesign + Claude Code / Claude 4.8 得分 78.32，比 Claude Design 高 7.45 分；七个固定 coding-agent/模型组合接入 DesignHarness 后，平均分从 54.99 提升至 67.39。这些均应视为作者自报结果。
- **为什么值得关注：**它不仅交付一个成品生成器，还尝试把评价、接受门和 Harness 演化做成可检验研究对象。这为“如何评估系统层 Agent 改进”提供了一个比单轮输出偏好更具体的切入点。
- **研究边界：**论文标注为 Tech Report，未显示同行评审状态；其正式验证对象是学术海报，不能据此推断对任意图文、幻灯片或视频生成任务的泛化效果。

## 趋势 / 编辑简评

今天的共同线索不是“更自主”，而是**让自主行为可看见、可评估、也可拒绝**。Fan 把人类接管放在真实网页操作的关键关口；AutoDesign 用评估和接受门筛选对 Harness 的更新；ACID-Agent 则把执行结果放到证据检查后再提交。三者都不能替代最小权限、沙箱、备份、独立测试或人工责任，但它们指向相同的工程原则：能力越接近改变现实状态，系统越需要暴露中间证据、明确确认点，并保留可回退的记录。
