## 今日要点

1. **有破坏力的工具调用，需要把“人类确认”设计成流程的一部分。**新发布的 macOS 清理 Skill 把扫描与删除分开，并把数据唯一副本、容器目录等情形列为高风险。
2. **Agent 代码评测不能把“测试通过”当作安全。**VibeSec 将 exploit 是否仍能触发、以及正常规格是否仍通过，作为两道独立门槛。
3. **公开基准不等于最终认证。**VibeSec 也明确提示其数据为公开 inspect set、任务局限于 FastAPI/Python，且类别分布不均；应用侧仍应保留私有回归集和人工安全审查。

## 开源项目

### macOS Disk Cleanup Skill：为可能删除文件的 Agent 加上可见的确认点

![macOS Disk Cleanup Skill 的 GitHub 仓库社交预览图](https://opengraph.githubassets.com/1/himynameisben/macos-disk-cleanup)

*图：GitHub 为该公开仓库生成的社交预览图；原始来源：[himynameisben/macos-disk-cleanup](https://github.com/himynameisben/macos-disk-cleanup)。图片无法加载时，请以仓库 README 的文字说明为准。*

- **首次公开：**GitHub 仓库创建于 **2026-08-06 06:56 UTC**；许可证为 MIT。
- **项目：**[himynameisben/macos-disk-cleanup](https://github.com/himynameisben/macos-disk-cleanup)。
- **项目自述：**面向 Claude Code、Codex 等 Agent 的 macOS 磁盘清理 Skill。README 提供只读扫描脚本，覆盖 `~/Library`、Xcode/Simulator、语言包管理器缓存、稀疏文件与孤儿容器等检查；同时把拟处理项分为 SAFE、CONFIRM、DANGER 三类，并要求即使是 SAFE 项也经确认后才删除。
- **为什么值得关注：**这是一个很具体的“权限与交互设计”案例：同样是“释放空间”，扫描可默认只读，删除却必须带上路径、后果和确认。对能够调用 shell 或文件系统的 Agent 来说，这种将可逆性、数据归属和人工核准显式化的模式，比在提示词中笼统要求“谨慎”更可执行。
- **采用提示：**项目作者明确警告：分级是给 AI 的指导，而不是技术强制锁；AI 仍可能误判。不要把它当作自动清理器运行。使用前应确认备份，逐项审阅删除列表；特别是 `Documents`、`Group Containers` 和不熟悉路径，应先查看内容而非直接批准。

## 论文 / 研究

### VibeSec：用行为验证衡量编码 Agent 的安全补丁

- **首次公开：**GitHub 仓库创建于 **2026-08-06 04:02 UTC**；许可证为 MIT。
- **项目：**[muence-ai/vibesec](https://github.com/muence-ai/vibesec)。这是一项开源基准发布，**不是同行评审论文**。
- **项目自述：**v1.0.0 含 1,000 个 FastAPI/Python 安全修补任务，覆盖 IDOR、缺失鉴权、批量赋值、权限提升、路径遍历与 SQL 注入等类别。每个任务都附带会在脆弱版本触发的 exploit、功能规格测试和参考补丁；评分时重新运行 exploit 与规格测试，不根据模型或人工对补丁“看起来安全”的判断计分。
- **为什么值得关注：**它把安全修补拆成两个不能相互替代的问题：攻击是否真的被阻断，以及修补是否破坏原有功能。对于部署 coding agent 的团队，这比单纯的单元测试成功率更贴近风险控制；仓库还公开了每个模型—任务的结果记录，便于复核汇总结果。
- **解读边界：**该项目的 `PROVENANCE.md` 明确指出：全部应用均为模型生成、每项约两个文件，68.8% 的任务是 IDOR，且数据集公开、可能被后续模型见过。因此它适合诊断与复现，不能单独用来证明某个新模型已具备生产级安全性。

## 趋势 / 编辑简评

今天两个条目看似分属桌面维护与安全评测，实际都在回答同一个问题：**当 Agent 开始改变系统状态，怎样让结果可检查、责任可回溯？**前者把删除前的判断和人类确认拆开；后者把“安全”从语言评价变成可执行的攻击与功能验证。它们并不能替代权限隔离、备份、沙箱或独立审计，却提示了一个工程方向：高风险行动应带有明确的前置条件、可观测证据和失败语义，而不是只期待模型始终做对。
