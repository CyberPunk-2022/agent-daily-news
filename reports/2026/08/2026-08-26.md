## 今日要点

1. **指令也需要生命周期管理。**Skill Sunset 把过时路径、重复 Skill、凭据痕迹和“可能已过时”的补偿规则分开处理，并明确禁止自动删除。
2. **长任务的核心不是“记住聊天”，而是提交证据。**HALT 以 append-only journal 记录状态，只有写入、注册、校验并提交的产物才算 DONE。
3. **测试 Agent 需要接近生产、但不能污染生产。**Antifailure 的定位是每个 PR 都复制一份可丢弃的生产栈，并隔离外部 API，方便让 Agent 跑真实流程。

## 开源项目

### Skill Sunset：审计并安全退役陈旧的 Agent 指令

![Skill Sunset 官方报告示例](https://raw.githubusercontent.com/ooocooc/open-skill-sunset/main/docs/assets/skill-sunset-report.png)

*图：项目仓库中的官方报告示例；原始来源：[ooocooc/open-skill-sunset](https://github.com/ooocooc/open-skill-sunset)。*

- **首次公开：**GitHub API 显示仓库创建于 **2026-08-26 02:55 UTC**，MIT 许可证，采集时 71 stars。
- **项目自述：**`skill-sunset` 扫描 `AGENTS.md`、`CLAUDE.md` 和 `SKILL.md`，检查断裂引用、过时绝对路径、格式问题、超大常驻文件、可能的明文凭据及同名 Skill；可输出 HTML、Markdown、JSON、交接提示、实验模板和回滚清单。
- **为什么值得关注：**Agent 系统的上下文预算和行为边界同样会“腐化”。把发现分为 `UPDATE`、`DEMOTE`、`RETIRE`、`TEST`，并把执行与验证分离，比直接删规则更适合团队治理。
- **边界：**仓库明确说明 `TEST` 只是待验证假设；审计核心不调用模型 API，也不代表发现一定真实或删除一定安全。

### HALT：让长时间 Agent 从崩溃中可验证地恢复

- **首次公开：**GitHub API 将 `gootf/halt-long-horizon-tasks` 列为 2026-08-26 创建的公开仓库，MIT 许可证。
- **项目自述：**HALT 提供规范、可安装的 Agent Skill 和零依赖 Python 参考运行时。其状态机要求产物先落盘，再注册、校验和、验证，最后才允许 DONE；恢复时从 append-only journal 重建合法起点。
- **为什么值得关注：**这给“Agent 说自己完成了”增加了一个可执行的反例：没有可定位、可校验的 artifact，就不能把聊天中的 DONE 当成事实。对批处理、跨会话编程和多执行器接力尤其有用。
- **边界：**参考运行时目前是单节点、单写入者；规范中的并行派发、嵌套和跨任务记忆尚未成为运行时能力。

### Antifailure：让 Agent 在隔离的生产副本里跑真实流程

- **首次公开：**GitHub API 显示 [antifailure/antifailure](https://github.com/antifailure/antifailure) 创建于 2026-08-26；API 未返回可识别的 SPDX 许可证，使用前应核实授权范围。
- **项目自述：**每个 Pull Request 都可获得脱敏的 Postgres 分支、第三方 API 沙箱、真实用户流程和负载回放，目标是让 AI Agent 在接近生产的条件下验证变更。
- **为什么值得关注：**Agent 评测若只跑静态单元测试，常漏掉权限、状态迁移和外部依赖交互。隔离副本把“真实流程测试”纳入代码审查循环。
- **边界：**这是项目定位和仓库描述，不足以证明沙箱隔离强度、数据脱敏质量或适合所有合规场景；采用前应审阅实现与威胁模型。

## 趋势 / 编辑简评

今天的三个项目把可靠性落在不同层：Skill Sunset 管理“规则资产”，HALT 管理“进度资产”，Antifailure 管理“环境资产”。共同点是把隐含状态变成可检查的文件、日志、隔离边界和接受门。对 Agent 工程团队而言，一个实用的最小闭环是：规则可审计、产物可校验、环境可回收；模型能力提升后，也要能证明旧约束是否真的可以安全退役。
