## 今日要点

- **流程被产品化为技能包。** `productwright` 将开发生命周期、独立审查、工作树隔离和验证约束组合为可安装的 Agent 工具集。
- **视觉还原从“看起来差不多”转向评分门槛。** `Replica` 的比较工具让 Agent 根据具体差异继续修正，而不是只输出一次实现。

## 开源项目

### productwright：把多 Agent 产品开发拆成带验证门槛的流程

[productwright](https://github.com/AnwarAndargie/productwright) 于 11 月 2 日创建，采用 MIT 许可证。维护者将其定位为面向任意技术栈和 Agent 的产品开发流程：从 preflight、发现与规划，到骨架、里程碑、加固、发布、上线和运营。仓库提供两个技能、审查/执行 Agent 定义、并行协作脚本及模板；README 还明确要求以测试、实际命令输出和独立审查来支撑交付声明。

它值得关注，并非因为它发明了新的模型能力，而是把多 Agent 的常见失误——无边界并行、未验证的完成声明、工作区互相污染——转译成可执行的流程约束。团队评估时仍应自行审查脚本、权限和依赖，并按自身合规要求调整“发布”“部署”等高影响步骤。

来源：[GitHub 仓库与 README](https://github.com/AnwarAndargie/productwright) · [GitHub API 元数据](https://api.github.com/repos/AnwarAndargie/productwright)

### Replica：用布局、样式、像素与动效评分约束 UI Agent

![Replica 官方演示：Agent 根据比较报告逐轮修正 UI 还原结果](https://raw.githubusercontent.com/albertirgi/replica/main/.github/assets/demo.gif)

*图：项目 README 链接的官方演示 GIF，展示其比较与修正流程。原始来源：[Replica README](https://github.com/albertirgi/replica#replica)。*

[Replica](https://github.com/albertirgi/replica) 于 11 月 2 日创建，采用 MIT 许可证。它是一个面向 Claude Code 等编码 Agent 的技能：对网站、截图或录屏建立参考描述，再将实现与参考按布局、样式、像素和动效四个轴比较；命令在设定门槛未通过时以非零退出，并产出按影响排序的差异报告。README 同时说明其需要 Node.js、浏览器自动化环境，视频/GIF 参考另需 `ffmpeg`。

这类工具值得关注，因为它为“把设计还原出来”这类长期依赖人工目测的任务提供了可重复的反馈回路。限制也同样清楚：分数只衡量选定参考和视口下的相似度，不替代无障碍、业务语义、性能或版权审查；项目也提醒使用方应拥有参考字体、图片、图标与文案的相应权利。

来源：[GitHub 仓库与 README](https://github.com/albertirgi/replica) · [GitHub API 元数据](https://api.github.com/repos/albertirgi/replica)

## 趋势 / 编辑简评

今天的两个项目指向同一个务实变化：Agent 正从“会生成”走向“生成后如何被约束和核验”。`productwright` 将约束放进开发流程和协作边界，`Replica` 将约束放进可量化的输出比较。对采用 Agent 的团队而言，下一步不妨先定义三件事：什么结果算通过、由谁复核、在未通过时系统应如何继续或停止。把这些问题留给提示词临场决定，往往比模型能力本身更容易造成交付偏差。
