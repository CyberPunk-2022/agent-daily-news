## 今日要点

- **技能不只是提示词。** 两个今天创建的开源项目都将任务边界、输入输出和限制写进了仓库：一个面向架构图交付，一个面向磁盘状态检查。
- **安全设计应包含“能证明没做什么”。** `voltdir` 声明只读取元数据、不读取文件内容、不联网、不提权；这类约束仍应由使用方自行审计和测试。
- **企业部署进入精细治理阶段。** Claude Code 的分层策略和池化群组预算，反映出 Agent 的运行成本与权限不再适合只用单用户设置管理。

## 开源项目

### stack-diagram：把技术栈描述交给 Agent 生成架构图

![stack-diagram 官方示例：Next.js、Hono、Neon、Clerk、Stripe 与 GitHub Actions 的架构图](https://raw.githubusercontent.com/caru-ini/stack-diagram/main/docs/hero.png)

*图：仓库 README 提供的官方示例图。原始来源：[stack-diagram README](https://github.com/caru-ini/stack-diagram#stack-diagram)。*

[stack-diagram](https://github.com/caru-ini/stack-diagram) 于 11 月 1 日公开，采用 MIT 许可证。维护者将其定义为一项 Agent skill：用户用一句话描述技术栈，技能生成架构图，并在 README 中说明可输出自包含 HTML、PNG、无依赖 React 组件或 Artifact。项目宣称会从 svgl、devicon、gilbarbara/logos 或品牌官方来源获取标识，且生成时会渲染并检查图形。

它值得关注，因为它把“画图”从泛化的图像请求收束为带明确交付格式和品牌素材来源规则的工程任务。团队应注意第三方商标使用规则、生成图是否准确反映真实部署，以及其运行时网络访问与 Playwright/Chromium 依赖。

来源：[GitHub 仓库与 README](https://github.com/caru-ini/stack-diagram) · [GitHub API 元数据](https://api.github.com/repos/caru-ini/stack-diagram)

### voltdir：面向 Windows 磁盘排查的只读 Agent 工具

![voltdir 官方横幅：Your disk, explained in one call](https://raw.githubusercontent.com/CubeLink-oss/voltdir/main/assets/en/banner.svg)

*图：仓库 README 的官方横幅。原始来源：[voltdir README](https://github.com/CubeLink-oss/voltdir#voltdir)。*

[voltdir](https://github.com/CubeLink-oss/voltdir) 于 11 月 1 日公开，采用 Apache-2.0。README 将它定位为 Windows x64 的单文件磁盘分析工具：`overview`、`report`、`find` 与 `diff` 均输出稳定 JSON；它可在权限允许时使用 NTFS MFT，否则回退到目录遍历。项目还附带可被 Claude Code 插件加载的 Agent skill，并公开了基准脚本与“不占优”场景。

它的价值在于把“磁盘为什么满了”这种易触及大量文件的任务，改造成只读、可保存索引/快照、带覆盖范围与退出码的工具契约。README 的速度和内存结果是维护者在给定环境下的中位数测试，尚非独立复现；且随仓库提供的二进制未代码签名，部署前应按项目说明自行构建或校验哈希。

来源：[GitHub 仓库与 README](https://github.com/CubeLink-oss/voltdir) · [GitHub API 元数据](https://api.github.com/repos/CubeLink-oss/voltdir) · [基准方法与结果](https://github.com/CubeLink-oss/voltdir/blob/main/benchmarks/RESULTS.md)

## 业界动态

### Claude Code v2.1.316：增加分组预算、分层策略与子代理配置

Anthropic 于 10 月 31 日发布 [Claude Code v2.1.316](https://github.com/anthropics/claude-code/releases/tag/v2.1.316)。Release 新增 `CLAUDE_CODE_SUBAGENT_EFFORT`，可为未单独指定的子代理设定 effort；Claude apps gateway 新增可由成员共享的月度 `pooled_budget`、`managed.policy_mode: layered` 分层策略，以及 Bedrock guardrail 的输入标签配置。该版本还修复了退出后遗留 shell 命令、受限会话读取边界和多项网关/云会话问题，并公告 Opus 4.8 fast mode 的弃用计划。

这些更新说明 Agent 平台的生产问题正从“能否调用模型”转到“多人如何共用预算、多个规则如何叠加、子代理默认消耗多少资源”。Release 说明不能替代组织环境中的回归验证；升级前尤其应测试策略叠加顺序、预算 API 权限与现有模型路由。

来源：[v2.1.316 官方 Release](https://github.com/anthropics/claude-code/releases/tag/v2.1.316) · [Claude Code Releases](https://github.com/anthropics/claude-code/releases)

## 趋势 / 编辑简评

今天最值得留意的不是某个更大的 Agent 框架，而是 **Agent 的输入输出边界正在变得更具体**：`stack-diagram` 为视觉交付设定素材与格式，`voltdir` 为本机观察设定只读与 JSON 合约，Claude Code 则把群组成本、策略叠加和子代理 effort 纳入控制面。对团队来说，下一轮工具选型可优先问三个问题：它输出是否可复查？权限是否最小化？运行成本是否可按人、组和子任务追踪？
