## 今日要点

- **Code Mode 的工具更新更接近实时协议。** Codex 的连续提交先加入增量 code mode 工具定义，再把 incremental exec 更新接入 session；这让长任务的工具状态更容易被前端消费。
- **评测系统开始明确排除模型思考内容。** Google ADK 的修复让 judge 与 Vertex 指标停止对 model thoughts 计分，避免把内部推理文本误当成用户可见答案质量。
- **框架的“最后一公里”继续产品化。** CrewAI 1.15.37 的变更覆盖电子表格读取和 standalone agent 项目 scaffold，说明 Agent 框架竞争点正在延伸到输入适配与项目生命周期。

## 开源项目

### Google Agent Development Kit：v2.14.0 与评测边界修复

[google/adk-python](https://github.com/google/adk-python) 在官方主分支合并了 `v2.14.0` 发布提交，并随后加入 `LlmRequest.to_generate_content_body()`；同一时间窗口还修复 Runner toolset 引用计数，以及把 OAuth2 token exchange 移出事件循环。评测侧的 [dd7161f](https://github.com/google/adk-python/commit/dd7161f7a2b88cd7ae482cc2acd8423675ac027c) 明确让 judge 和 Vertex metrics 停止对 model thoughts 计分。

它值得关注，因为 Agent 评测很容易被“模型说了什么”与“任务最终完成了什么”混在一起。把 thoughts 从评分输入中排除，有助于降低实现细节泄漏和指标漂移；采用者仍应核对自身 evaluator 是否以最终响应、工具轨迹或业务结果为准。

来源：[官方仓库](https://github.com/google/adk-python) · [v2.14.0 合并提交](https://github.com/google/adk-python/commit/5c4fa928548b5969bd61d2d8a1c1c7c813c49b33) · [评测修复](https://github.com/google/adk-python/commit/dd7161f7a2b88cd7ae482cc2acd8423675ac027c)

### CrewAI：1.15.37 将文件输入与项目脚手架纳入主线

CrewAI 官方仓库在 2026-11-07 UTC 的提交中将版本提升到 [1.15.37](https://github.com/crewAIInc/crewAI/commit/c9e51e8b3c7509f3c55cafe9a0ae2b1b44f3db41)，并同步合并了 `crewai-files` 读取电子表格的能力（[bf5ea11](https://github.com/crewAIInc/crewAI/commit/bf5ea11fc31398d4dd89be28da01097a63f37bb1)）以及 standalone agent 项目 scaffold/load（[069bbb2](https://github.com/crewAIInc/crewAI/commit/069bbb255bb56d48c8c69754d1f0d67fd5599683)）。

这类变更不等于模型能力跃迁，却直接影响 Agent 是否能进入真实工作流：表格是常见业务输入，脚手架则降低新项目从示例到可维护代码的成本。升级前应查看完整 changelog，并在锁定的 Python 依赖环境中验证文件权限、格式兼容性和生成项目的默认配置。

来源：[官方仓库](https://github.com/crewAIInc/crewAI) · [1.15.37 版本提交](https://github.com/crewAIInc/crewAI/commit/c9e51e8b3c7509f3c55cafe9a0ae2b1b44f3db41) · [电子表格支持](https://github.com/crewAIInc/crewAI/commit/bf5ea11fc31398d4dd89be28da01097a63f37bb1) · [独立项目脚手架](https://github.com/crewAIInc/crewAI/commit/069bbb255bb56d48c8c69754d1f0d67fd5599683)

## 业界动态

### OpenAI Codex：Code Mode 接入增量 exec 更新

OpenAI Codex 官方仓库连续提交 [2bc8e7f](https://github.com/openai/codex/commit/2bc8e7f5459b084afa482c7aac3f56fef36286b3) 与 [33b3f80](https://github.com/openai/codex/commit/33b3f80a0935e51a49cbbda7d6473ef757d4241b)，分别加入 incremental code mode tool definitions，并将 incremental exec tool updates 接入 Code Mode sessions。提交时间为 2026-11-07 UTC，属于官方代码变更，不是面向终端用户的独立产品公告。

它值得关注，因为 Agent 客户端需要知道“工具定义变了”与“工具正在执行”是两个不同事件。增量更新可以减少等待完整响应的空窗，但也要求调用方正确处理事件顺序、断线重连和 rollout trace 重放；这些提交本身没有宣称所有客户端都已默认启用。

来源：[增量工具定义](https://github.com/openai/codex/commit/2bc8e7f5459b084afa482c7aac3f56fef36286b3) · [增量 exec 接入](https://github.com/openai/codex/commit/33b3f80a0935e51a49cbbda7d6473ef757d4241b) · [Codex 官方仓库](https://github.com/openai/codex)

## 趋势 / 编辑简评

今天的共同主题是“运行时可见性”：工具定义、执行进度、评测输入和项目文件都被拆成更明确的边界。Agent 系统要真正进入生产，除了能完成任务，还要让调用者知道当前状态、评测究竟测了什么，以及升级后哪些输入契约发生变化。建议团队把事件顺序、评测字段和文件权限纳入回归测试，再扩大自动化范围。
