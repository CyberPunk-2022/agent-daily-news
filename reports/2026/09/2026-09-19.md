## 开源项目

### Everything Search Skill：让本地文件搜索成为受控的 Agent 工具

- **首次公开：**GitHub API 显示仓库创建于 **2026-09-19 06:08 UTC**，MIT 许可证，采集时 33 Stars。
- **项目：**[Mayuqi-crypto/everything-search-skill](https://github.com/Mayuqi-crypto/everything-search-skill)。
- **项目自述：**该 skill 通过 Voidtools Everything 的索引检索本地文件，提供 PowerShell/Python 包装脚本、`--json` 结构化输出、`-path` 工作区范围和默认结果上限；README 宣称典型查询低于 15 ms，并兼容 Cursor、Codex、PI-Desktop 等环境。
- **为什么值得关注：**递归 `find` 或无界 glob 很容易把依赖目录和构建产物灌进上下文。把“范围”和“数量上限”编码进工具接口，可减少 Token 浪费，也让 Agent 的文件发现行为更容易审计。
- **采用提示：**项目要求 Windows 10/11 与正在运行的 Everything；“低延迟”是作者测试口径，不代表所有磁盘规模和负载。安装脚本会写入用户目录，部署前应审阅脚本与二进制来源。

### Miro：在终端里并置内置 Agent 与 ACP

![Miro 官方仓库的项目标识](https://raw.githubusercontent.com/metowolf/miro/main/logo.png)

*图：Miro 官方仓库 `logo.png`；原始来源：[metowolf/miro](https://github.com/metowolf/miro)。*

- **首次公开：**GitHub API 显示仓库创建于 **2026-09-19 03:56 UTC**；未声明 SPDX 许可证，采集时 1 Star。
- **项目：**[metowolf/miro](https://github.com/metowolf/miro)。
- **项目自述：**Miro 是基于 Bun、React 与 Ink 的终端客户端，提供交互式 TUI 和一次性打印模式；内置 Agent 可直接调用 Chat Completions、OpenAI Responses 或 Anthropic Messages，并可用 `--acp <provider-id>` 通过 stdio JSON-RPC 启动 ACP 提供方。
- **为什么值得关注：**它把“客户端 UI/会话能力”和“Agent 提供方”拆成两层：用户可以保留统一的终端工作流，同时替换后端 Agent。这种组合方式有助于降低工具锁定，但也把协议兼容、权限提示和会话恢复交给客户端与提供方共同保证。
- **采用提示：**README 仍处于早期项目形态，许可证缺失意味着分发或嵌入前应先向维护者确认授权；ACP 通道的安全边界还应结合具体子进程审阅。

## 新概念：ACP 作为客户端—Agent 提供方的组合层

Miro README 明确链接 [Agent Client Protocol](https://agentclientprotocol.com/)，并把 ACP 提供方作为可选子进程接入，而不是把所有 Agent 逻辑硬编码在客户端内。对开发者而言，ACP 的实际价值不在于又一个“模型 API”，而在于它约定了客户端与编码 Agent 之间的交互边界。今天能确认的是 Miro 的接入方式；协议生态的实现数量、兼容性和安全实践仍需要后续逐项核验。
