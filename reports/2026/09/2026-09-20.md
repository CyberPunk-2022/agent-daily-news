## 今日要点

1. **Agent 编排开始先处理控制面。**Helm 的探测、路由和监督脚本分别承担观察、决策与结果判断，降低“随便选一个 CLI”带来的成本和失败重试。
2. **上下文治理正在变成显式数据模型。**Mosaic 用 typed slots、lenses、事务和 token budget 描述不同消费者真正需要看到的状态。
3. **浏览器自动化正在从一次性脚本走向可运营任务。**AegisCrawler 把录制、规则审阅、租约、心跳、死信队列和指标放进同一条链路。

## 开源项目

### Helm：为现有编码 Agent 提供路由与监督层

- **首次公开：**GitHub API 显示仓库创建于 **2026-09-20 02:09 UTC**，许可证为 MIT。
- **项目：**[Jimuelle07/Helm](https://github.com/Jimuelle07/Helm)。
- **项目自述：**Helm 可作为 Claude Code 插件、Gemini CLI 扩展或 Agent Skill 使用，面向 Claude Code、Codex、Cursor、Gemini CLI、Aider、OpenCode、Copilot 及本地模型。`probe.py` 发现安装与认证状态，`route.py` 选择候选 Agent，`supervise.py` 则读取执行结果判断是否完成；项目还使用非生成式 TypeSafe Jev 做结构化决策。
- **为什么值得关注：**很多团队已经同时安装多个 coding agent，却把选择、权限检查和“任务是否真的做完”留给人工。Helm 把这些判断抽成可替换的控制面，尤其适合需要比较成本、上下文窗口和专业能力的本地工作站。
- **采用边界：**README 的成本、置信度与完成判断是项目方设计和演示，不是跨模型基准。路由前仍应检查凭据、命令参数和工作目录；自动执行与人工确认的门槛需要按风险调整。

### Mosaic：让上下文成为有生命周期的状态层

- **首次公开：**GitHub API 显示仓库创建于 **2026-09-20 01:22 UTC**，许可证为 MIT。
- **项目：**[detailles/Mosaic](https://github.com/detailles/Mosaic)。
- **项目自述：**Mosaic 提供 typed slots、所有权约束、consume-once/turn-scoped 生命周期、static/transient/internal 持久性，以及 lenses 形式的只读范围视图；事务支持回滚，token allocation 用于在预算紧张时优先保留高价值状态。
- **为什么值得关注：**当 Agent 由路由器、检索器和执行器组成时，所有组件共享一个不断增长的消息数组会让“谁改了什么”“模型看到了什么”难以追踪。显式 slot 和 lens 能把上下文边界写成代码契约，为审计和回归测试提供落点。
- **采用边界：**README 的类型安全、预算分配和 lens 约束仍需结合实际模型提示与应用测试验证；上下文管理库本身不会保证事实准确或自动解决提示注入。

### AegisCrawler：把浏览器录制转成可调度、可审计任务

![AegisCrawler 官方 README 中的录制与 DSL 演示](https://raw.githubusercontent.com/singhand-labs/AegisCrawler/main/.github/assets/demo.gif)

*图：官方 README 的 PageResearch Agent 演示；原始来源：[singhand-labs/AegisCrawler](https://github.com/singhand-labs/AegisCrawler)。图片无法加载时，请以仓库 README 和文字说明为准。*

- **首次公开：**GitHub API 显示仓库创建于 **2026-09-20 10:01 UTC**，许可证为 GPL-3.0。
- **项目：**[singhand-labs/AegisCrawler](https://github.com/singhand-labs/AegisCrawler)。
- **项目自述：**PageResearch Agent 扩展记录真实页面上的点击、输入、滚动和拖拽，生成 YAML/JSON DSL；Go 服务负责 SQLite 存储、任务租约、心跳、重试、死信队列和 Prometheus 指标；ScriptCat worker 在真实浏览器标签页执行规则。可选的 LLM 增强会先进行安全扫描和 diff 审阅，再等待人工批准。
- **为什么值得关注：**浏览器 Agent 的难点不只是生成一次能跑的脚本，而是任务失联、重试、凭据、变更审阅和长期可观测性。AegisCrawler 将“录制速度”和“生产运维”拆成两层，体现了从 demo 到服务化的工程路径。
- **安全与采用边界：**README 要求 TLS、强随机 API key 和加密密钥，并明确生产 LLM 模式需要预算、价格表和尝试次数限制。真实浏览器自动化仍可能触及敏感数据；上线前必须隔离账户、站点和密钥，并审阅每次规则变更。

## 趋势 / 编辑简评

今天的共同线索是：Agent 的竞争焦点从“能不能调用工具”转向“能否被控制、解释和持续运行”。Helm 处理的是多 Agent 的选择与结果监督，Mosaic 处理的是上下文的所有权和预算，AegisCrawler 处理的是浏览器任务的生命周期与人工变更门。三者都把隐性过程变成可检查对象，但都不能替代真实环境测试：路由分数不等于任务成功率，类型化上下文不等于事实可靠，安全扫描也不等于浏览器隔离。采用时应先定义证据、权限、回滚和人工接管条件，再逐步提高自动化程度。
