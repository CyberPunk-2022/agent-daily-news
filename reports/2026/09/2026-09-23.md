## 今日要点

1. **Agent 的体验层正在桌面化。**CodexDesk 将编程 Agent 工作流包装为原生、跨平台客户端；其公开 README 目前只给出简短的功能概述，实际集成范围仍须以代码与发行包为准。
2. **快速执行必须伴随受限动作空间。**laya-ultrafast 不让模型直接生成选择器、坐标、Shell 或 JavaScript，而是从已观测的 DOM 节点中选择动作。这是一种值得复用的约束思路，但不构成对浏览器自动化安全性的完整证明。
3. **评测正在从“哪个模型更强”扩展到“哪套执行框架更可靠”。**evalix 的定位把工具调用、长程任务与成本效率放在一起，提醒团队评估 Agent 时同时记录任务结果、失败模式和资源消耗。

### laya-ultrafast：把浏览器 Agent 的选择约束在已索引的页面动作中

![laya-ultrafast 官方 Google Flights 演示](https://raw.githubusercontent.com/xuancuongdoo/laya-ultrafast/main/docs/demo.gif)

*图：laya-ultrafast README 中的 Google Flights 演示。原始来源：[xuancuongdoo/laya-ultrafast](https://github.com/xuancuongdoo/laya-ultrafast)。图片无法加载时，可查看[官方 MP4](https://github.com/xuancuongdoo/laya-ultrafast/blob/main/docs/demo.mp4)。*

- **首次公开：**GitHub API 显示仓库创建于 **2026-09-23 07:29 UTC**，许可证为 **MIT**；本期采集时为 6 stars。
- **项目：**[xuancuongdoo/laya-ultrafast](https://github.com/xuancuongdoo/laya-ultrafast)。
- **项目自述：**该 Python MVP 使用本地 Laya 服务选择操作与目标；每个页面快照先被索引为元素表，只允许 `CLICK`、`TYPE_TEXT`、`SELECT`、`DONE`、`BLOCKED` 等操作。README 称大页面会先短名单化至每批不超过 10 个候选，字段文本可由兼容 OpenAI API 的小模型填写，并提供一次 Google Flights 航班搜索演示。
- **为什么值得关注：**浏览器 Agent 的脆弱点通常不是“能否生成一段指令”，而是指令是否指向当前页面真实存在、且被允许操作的目标。将模型输出限制为观察到的节点和有限操作，有利于降低幻觉选择器与不可审计执行的范围，也让失败更容易定位。
- **边界说明：**README 所称约 6.5 秒演示时延、100–190 ms 决策时延和零决策成本均为项目方测量或设定，并非独立基准。项目也明确其 DOM 阅读器暂不覆盖 shadow root、frame、canvas、上传、弹窗标签页与嵌套滚动；`DONE` 仍需独立验证结果。

## 趋势 / 编辑简评

今天的三个项目处在 Agent 系统的不同层：CodexDesk 面向操作者，laya-ultrafast 面向运行时决策，evalix 面向评估。它们共同提示，Agent 的价值不只取决于“模型能不能回答”，还取决于人是否能接管、系统是否只做被允许的动作，以及团队是否能测量成功之外的代价。

这并不意味着这些项目已经解决了桌面安全、浏览器自动化或评测有效性。更稳妥的采用顺序是：先从无敏感数据、可回滚的任务开始；检查模型、浏览器和桌面之间的数据流；为每次关键动作保留可验证证据；再依据真实成本与失败率决定是否扩大权限和使用范围。
