## 今日要点

- **Agent 客户端开始围绕“需要人介入的时刻”设计。** Harp 的侧栏区分 working、waiting、done 等状态，并用 tmux 保存分组和顺序；这直接对应多任务并行时的注意力分配问题。
- **调度基础设施成为 Agent 技能的一部分。** GenPark 的技能解析 crontab 并加入分布式 jitter，且声明兼容 MCP；它解决的是自治集群的运行时节奏，而不是模型能力本身。
- **多模态 Agent 的增益来自可复核的外部证据。** OpenVLHarness 将图片、结构化数据和网页引用作为可寻址记忆保存，提醒工程团队把工具输出的呈现格式和生命周期纳入评测。

## 开源项目

### Harp：面向长运行编码 Agent 的 macOS 侧栏

![Harp 官方仓库预览](https://opengraph.githubassets.com/1/dominikmartn/harp)

*图：Harp 官方仓库预览。原始来源：[dominikmartn/harp](https://github.com/dominikmartn/harp)。*

[Harp](https://github.com/dominikmartn/harp) 于 2026-10-20 创建，仓库公开指标显示 159 stars，采用 AGPL-3.0。README 将其描述为 Warp 的非官方开源 fork：在 macOS 终端中并排运行 Claude Code 与 Codex，会话侧栏显示工作、等待、完成和未读状态，并通过 tmux 持久化分组。它值得关注，是因为 Agent 使用体验的瓶颈常常是“哪个任务需要我”，而不是再增加一个聊天面板。项目明确称登录 Harp 尚未充分测试，且上游 Warp 的云功能仍按上游方式通信；企业采用前应审阅许可证、账号和网络边界。

### GenPark Cron Jitter Scheduler：MCP 原生的集群调度技能

![GenPark Cron Jitter Scheduler 官方仓库预览](https://opengraph.githubassets.com/1/alphaparkinc/genpark-cron-jitter-scheduler-agent-skill)

*图：GenPark 技能仓库预览。原始来源：[alphaparkinc/genpark-cron-jitter-scheduler-agent-skill](https://github.com/alphaparkinc/genpark-cron-jitter-scheduler-agent-skill)。*

[GenPark Cron Jitter Scheduler Agent](https://github.com/alphaparkinc/genpark-cron-jitter-scheduler-agent-skill) 于 2026-10-20 创建，README 声明使用 Python 标准库、提供 MCP server，并通过分布式 jitter 避免自治 Agent 集群在同一时刻触发大量任务。这个项目的价值在于把 cron 解析、抖动策略和 Agent 工具接口放在一起，便于在 DAG 或桌面客户端中复用；不过“production resilience”等描述仍是项目自述，部署前需要自行压测丢失、重复和时钟漂移场景。

| [OpenVLHarness: Real World Visual Agentic Tool-Use with Multimodal Memory](https://arxiv.org/abs/2610.26860) | 为视觉 Agent 提供能力层、证据渲染、持久多模态记忆和对存储数据执行代码的接口；在 22 个基准上比较工具使用与无工具基线。 | 把“工具结果如何呈现、如何跨步骤保留”变成系统设计问题；论文报告相对基线平均提升 9.7–12.6 分，但这是预印本结果，不能直接等同于生产收益。 |
| [Can It Actually Work? Synthesizing Functional CAD Mechanisms](https://arxiv.org/abs/2610.26861) | 提出 FunCAD-Harness 与 46 类机构的 FunCADBench，用候选机构的物理测试和模拟反馈检验 Agent 生成的 CAD 是否真正可工作。 | 从外观合理推进到功能验证，说明 Agent 评测应覆盖真实约束和失败模式，而不只看生成结果是否“像对的”。 |

## 趋势 / 编辑简评

今天的共同主题是 **“Agent 的第二层基础设施正在成形”**：Harp 处理人的注意力和会话状态，GenPark 处理机器群的时间协调，OpenVLHarness 处理工具证据的可解释记忆。下一步评测不应只问 Agent 能否完成一次任务，还应记录它何时请求人、是否能在拥塞时退避、以及跨步骤保存的证据能否被复核。
