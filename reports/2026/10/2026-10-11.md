## 开源项目

### OpenAI Agents SDK：把工具调用与交接做成可追踪工作流

- **项目：**[openai/openai-agents-python](https://github.com/openai/openai-agents-python)。
- **一手材料：**[官方 README](https://github.com/openai/openai-agents-python) 与 [OpenAI Agents SDK 文档](https://openai.github.io/openai-agents-python/)。
- **项目自述：**SDK README 将 agent、工具、handoff、guardrail、session 和 tracing 列为核心概念，并提供 Python 示例与运行方式。
- **为什么值得关注：**这些抽象把“模型决定下一步”与“系统允许做什么”分开，便于在工具调用前加入验证、在代理交接时记录上下文，并在运行后检查轨迹。它更适合作为工程接口参考，而不是质量或安全的自动证明。
- **采用提示：**实际部署仍需限制工具权限、隔离凭据、审阅追踪数据的敏感字段，并为模型服务不可用、工具超时和重复执行设计幂等策略。

### Model Context Protocol：把模型与外部能力的连接写成协议

- **项目：**[modelcontextprotocol/modelcontextprotocol](https://github.com/modelcontextprotocol/modelcontextprotocol)。
- **一手材料：**[官方规范](https://modelcontextprotocol.io/specification/latest) 与 [官方仓库](https://github.com/modelcontextprotocol/modelcontextprotocol)。
- **项目自述：**规范描述 host、client、server 之间的能力协商、资源、提示与工具调用边界，并要求实现遵循协议版本与生命周期规则。
- **为什么值得关注：**统一连接层可以减少 Agent 应用对单一工具适配器的耦合，也让权限、能力发现和错误处理有了共同的审查入口。协议互操作并不等于工具可信，调用方仍需逐项批准服务端能力。
- **采用提示：**接入第三方 MCP server 前，应核对代码来源、网络访问范围、返回内容是否包含提示注入，以及服务端是否会把输入转发给其他供应商。
