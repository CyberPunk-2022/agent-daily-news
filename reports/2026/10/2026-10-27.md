## 今日要点

- **可观测性开始面向人类注意力设计。** Soulgent 的 Duty Room、Office 和 Seaview 用状态、队列和团队空间呈现会话；Swarmstead 则把权限等待、循环、上下文压力、成本和潜在冲突做成可见事件。
- **“完成”正在从一句话变成一组检查。** DoneCheck 明确区分已验证、失败、证据不足和跳过，缺少证据不会被算作通过，这比单纯执行测试命令更接近 Agent 交付的现实。
- **上下文与后台执行仍需要细密的失败语义。** Claude Code 2.1.311 修复超大上下文继续执行、MCP 资源读取中断、后台子 Agent 工作树清理等问题；这类修复直接影响无人值守任务的可恢复性。

## 开源项目

### Soulgent：把每个 Agent 会话变成可巡检的角色

![Soulgent 官方项目概览](https://raw.githubusercontent.com/Ericcc0321/soulgent/main/docs/media/hero.png)

*图：Soulgent 官方 README 的跨设备概览图，展示 Mac、iPad 与 iPhone 上的会话状态。原始来源：[Soulgent README](https://github.com/Ericcc0321/soulgent#what-is-soulgent)。*

[Soulgent](https://github.com/Ericcc0321/soulgent) 于今日公开，采用 MIT 许可证。项目将 Claude Code、Codex、WorkBuddy 等会话映射为有名称、外观和状态的角色：工作中的会留在桌前，完成后到沙发等待，需要决策的会排队到用户桌边。Mac 原生菜单栏应用负责观察，移动 Web App 可在手机上回复 Claude Code 会话；README 也明确说明 Codex 与 WorkBuddy 当前主要提供状态和摘要，不能在手机端完整回复。

它值得关注的地方不是拟人化本身，而是把“会话管理”从日志检索变成注意力分配。部署时仍应阅读其安全模型：拥有管理密钥的人可以向会话输入内容，移动访问也会扩展控制面。

来源：[GitHub 仓库](https://github.com/Ericcc0321/soulgent) · [GitHub API 元数据](https://api.github.com/repos/Ericcc0321/soulgent) · [安全说明](https://github.com/Ericcc0321/soulgent/tree/main/webapp)

### Swarmstead：面向 Claude Code 的本地 Agent 观测村落

![Swarmstead 官方项目概览](https://raw.githubusercontent.com/ngoanpv/swarmstead/main/docs/images/tour-hero.gif)

*图：Swarmstead 官方 README 的功能演示图，展示会话、子 Agent、成本与异常提示。原始来源：[Swarmstead README](https://github.com/ngoanpv/swarmstead)。*

[Swarmstead](https://github.com/ngoanpv/swarmstead) 同日公开，采用 MIT 许可证，要求 Node 18+。它通过 Claude Code 插件和本地 daemon 记录会话摘要，在浏览器村落中显示权限等待、预算、测试声明、合并冲突、成本与上下文压力；README 称 Codex CLI 支持仍处于 beta。数据默认留在本机，项目文档还列出跨源请求、Host 校验、令牌和可选 webhook 的边界。

这类工具的价值在于把“Agent 正在做什么”变成一等工程信号。采用前应确认摘要采集范围、通知出口和本地令牌的权限，不能把可视化界面当成完整审计系统。

来源：[GitHub 仓库](https://github.com/ngoanpv/swarmstead) · [GitHub API 元数据](https://api.github.com/repos/ngoanpv/swarmstead) · [隐私与安全](https://github.com/ngoanpv/swarmstead#privacy--security)

### DoneCheck：用证据核对 Agent 的“已完成”

[DoneCheck](https://github.com/DemonPalace/DoneCheck) 于今日公开，采用 MIT 许可证，要求 Go 1.25+。工具可扫描泄露的密钥、不可解析文件、重复代码、Go 死代码、依赖漏洞与测试命令，并把每项结果标成 `VERIFIED`、`FAILED`、`INCONCLUSIVE` 或 `SKIPPED`。项目强调：超时、扫描器缺失或没有测试不能算通过；退出码 0 仅表示所有必需检查均已验证。

它把 Agent 交付中的“主张”和“证据”分开，是今天最直接的可靠性信号。限制也很清楚：命令执行由项目配置决定，`--allow-commands` 会运行配置中的检查，因此接入 CI 前应先审阅 `donecheck.json` 和安全模型。

来源：[GitHub 仓库](https://github.com/DemonPalace/DoneCheck) · [GitHub API 元数据](https://api.github.com/repos/DemonPalace/DoneCheck) · [安全模型与限制](https://github.com/DemonPalace/DoneCheck/blob/main/docs/security.md)

## 业界动态

### Claude Code v2.1.311：继续修补长上下文、MCP 与后台会话

Anthropic 在 10 月 27 日（北京时间）发布 [Claude Code v2.1.311](https://github.com/anthropics/claude-code/releases/tag/v2.1.311)。官方 release 新增 self-hosted runner 的 idle hold 选项，并修复超 200K token 后标准上下文会话停止、MCP 资源读取未响应时中断不生效、子 Agent 的 MCP 连接时序、后台子 Agent 工作树过早清理等问题；同时改进压缩、重试和后台 shell 的提示。

这些变化说明可靠性工作的重点已从“能否调用工具”转向“被打断、压缩或恢复时是否保持正确状态”。升级前应回归长会话、MCP 资源读取、后台任务和自动压缩，而不是只验证一次成功调用。

来源：[Claude Code v2.1.311 官方 Release](https://github.com/anthropics/claude-code/releases/tag/v2.1.311) · [Claude Code Releases](https://github.com/anthropics/claude-code/releases)

## 趋势 / 编辑简评

今天的共同主题是 **“Agent 数量增长后，状态与证据必须先于速度”**。Soulgent 和 Swarmstead 解决“我如何知道一群会话在做什么”，DoneCheck 解决“我凭什么相信它做完了”，而 Claude Code 的修复则提醒我们：状态显示只有在中断、压缩和恢复路径上仍然准确才有价值。下一轮 Agent 平台评审可以先问三件事：状态是否能区分等待与失败？完成是否带有可复核证据？无人值守任务能否在工具超时后安全恢复？
