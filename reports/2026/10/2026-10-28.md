## 今日要点

- **从一次性对话转向常驻工作。** Ravnir 的公开 beta 允许 Agent 在服务器上继续工作、运行例程，并将共享记忆以 Git 中的 Markdown 笔记呈现；用户可以审阅差异并撤回部分记忆改动。
- **多 Agent 产品把权限边界摆到台前。** Tucano 将不同 harness 放进频道式团队，并宣称敏感写操作需用户批准；其 README 同时说明数据留在 Mac。本期将这些视为项目公开设计，不代表已经独立验证其安全性。
- **评测对象从模型扩展到监督过程。** No, Actually... 读取本地 AI 对话历史，按明确规则统计用户指出错误的时刻。可解释的规则有助于复核，但“被纠正次数”也会受到对话风格、记录范围和规则误判影响。

## 开源项目

### Ravnir：自托管的持续 Agent 与可审阅记忆

![Ravnir 官方 README 首页截图，显示 Agent、当日支出与待运行例程](https://raw.githubusercontent.com/ravnir-ai/ravnir/main/docs/media/home.png)

*图：项目 README 中的 Home 页面截图，展示 Agent 状态、支出和例程。原始来源：[Ravnir 官方 README](https://github.com/ravnir-ai/ravnir#ravnir)。*

[Ravnir](https://github.com/ravnir-ai/ravnir) 于 10 月 28 日创建公开仓库，标注 MIT 许可，并称处于 `0.1.0` public beta。项目将 Agent 任务、独立浏览器、定时例程和共享 Markdown vault 放在自托管服务器；记忆变更以 Git 历史、差异和提案供用户检查。README 还展示了逐轮 token/cost 记录与预算上限。

它值得关注之处在于把持续运行与可审阅记忆放在同一产品里，而不是把长期记忆藏在不可见的提示词中。局限也应一并看到：公开文档仍注明 beta 会有破坏性变化，验证范围有限；将浏览器、shell 或桌面能力交给常驻 Agent 前，需先读安全模型和备份说明。

来源：[GitHub 仓库与 README](https://github.com/ravnir-ai/ravnir) · [GitHub API 元数据](https://api.github.com/repos/ravnir-ai/ravnir) · [安全模型](https://github.com/ravnir-ai/ravnir/blob/main/SECURITY.md)

### Tucano：Mac 上的多 Agent 团队与逐工具审批

![Tucano 官方 README 对话频道截图，展示 Agent 协作过程](https://raw.githubusercontent.com/eduwxyz/tucano/main/docs/images/conversation.png)

*图：Tucano README 中的频道示例，展示多个 Agent 交接任务。原始来源：[Tucano 官方 README](https://github.com/eduwxyz/tucano#channels-where-agents-work-together)。*

[Tucano](https://github.com/eduwxyz/tucano) 于 10 月 28 日创建公开仓库，采用 Apache-2.0 许可。README 描述它是一款面向 Apple Silicon Mac 的桌面应用：通过频道、角色与记忆组织 Claude Code、Codex、OpenCode 或 Pi；工具连接使用 MCP，并支持按 Agent 和工具设置无权、只读或读写权限。项目称合并、发帖、邮件等写入动作会等待用户审批，数据保存在本机。

这让“人类批准”成为 Agent 团队工作流的一部分，尤其适合需要跨工具协作但不希望 Agent 默默执行外部写操作的场景。采用时仍应阅读其权限说明并验证实际配置；README 中的产品承诺不是独立安全审计。

来源：[GitHub 仓库与 README](https://github.com/eduwxyz/tucano) · [GitHub API 元数据](https://api.github.com/repos/eduwxyz/tucano) · [安全说明](https://github.com/eduwxyz/tucano/blob/main/SECURITY.md)

### No, Actually...：把“纠正 AI”变成可检查的本地统计

[No, Actually...](https://github.com/HTMLGuyLLC/NoActually) 于 10 月 28 日创建公开仓库，采用 MIT 许可。维护者称它支持 Claude Code、Claude Cowork 和 Codex 的本地记录，并可导入 ChatGPT、Claude.ai 数据导出；其规则引擎区分确认、承认、用户主张和 AI 纠正用户等类别，不让模型来判定分数。项目也描述了来源授权、文本保留选项和脱敏机制。

它值得留意，因为它试图给“人类监督 AI”一个可检查的本地指标，同时明确披露规则逻辑，而非以黑盒模型做裁判。但计数不是能力排行榜：不同工具的记录格式、用户纠错习惯和规则边界都会影响结果。读者应先看隐私说明，再判断这些数字是否适合自己的使用场景。

来源：[GitHub 仓库与 README](https://github.com/HTMLGuyLLC/NoActually) · [GitHub API 元数据](https://api.github.com/repos/HTMLGuyLLC/NoActually) · [隐私说明](https://github.com/HTMLGuyLLC/NoActually/blob/main/PRIVACY.md) · [规则实现](https://github.com/HTMLGuyLLC/NoActually/blob/main/crates/engine/src/rules.rs)

## 趋势 / 编辑简评

今天的信号可以概括为 **Agent 从“会回答”扩展到“长期工作、团队协作与可衡量监督”**。Ravnir 把记忆和持续执行放到自托管环境，Tucano 将多 Agent 交接与工具权限编入桌面工作台，No, Actually... 则把用户纠正行为转成透明规则下的个人统计。三者共同提醒：产品能力越靠近真实数据和外部动作，持久状态、逐项授权、撤销能力与可解释记录就越重要。对新工具的评估，最好同时检查“能做什么”和“如何停下、审阅、撤回”。
