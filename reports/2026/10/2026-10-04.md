## 今日要点

1. **人类复核正被嵌入 Agent 创作流程。**Mesh Avatar Studio 不把 Agent 的输出当作终点，而是要求用户在本地编辑器中检查姿态、口型与图层。
2. **能力封装开始重视交互协议。**qiaomu-codex-imagegen 把“提案—选择—提示词展开—生成—验收”写成显式流程；这有助于追溯，但不保证生成结果或第三方能力在所有环境可用。
3. **安全评测要同时看意图与执行。**ScopeGuard 的实验设计提醒我们：硬性工具边界可以阻止越权动作，却未必阻止模型的规划过程受恶意内容影响。

## 开源项目

### Mesh Avatar Studio：让编码 Agent 参与建模，再由本地编辑器完成检查

![Mesh Avatar Studio 官方编辑器预览](https://raw.githubusercontent.com/shinshin86/mesh-avatar-studio/main/docs/images/en/01-overview.png)

*图：官方 README 的编辑器概览，展示示例角色及左右分栏的编辑/预览界面。原始来源：[Mesh Avatar Studio README](https://github.com/shinshin86/mesh-avatar-studio)。若图片无法加载，请查看该 README。*

- **首次公开：**GitHub API 显示仓库创建于 **2026-10-04 03:33 UTC**，采用 **MIT** 许可证；本期检索时为 105 stars。
- **项目：**[shinshin86/mesh-avatar-studio](https://github.com/shinshin86/mesh-avatar-studio)。
- **项目自述：**它将一张插画转为可眨眼、说话、转头的 2D mesh avatar。README 说明，Claude Code 或 Codex 先按项目指南准备头像；用户随后在本地编辑器拖动控制点、实时预览、做姿态与口型测试，并可让 Agent 生成绘制版眼睛和嘴型。
- **为什么值得关注：**它把 Agent 擅长的步骤化图像处理，与人擅长的视觉判断分开：前者产出可编辑工程，后者在可见预览中验收。这比一次性“生成成品”的黑箱交付，更适合需要持续微调的创作任务。
- **采用提示：**代码为 MIT，但 README 明确样例角色 Miko 不受该许可证覆盖，且另有使用条款。使用自有素材前也应检查图像权利、Agent 的本地文件权限，以及生成变体是否满足角色授权。

### qiaomu-codex-imagegen：把图像生成包装为可选择、可记录的 Agent 工作流

- **首次公开：**GitHub API 显示仓库创建于 **2026-10-04 08:47 UTC**，采用 **MIT** 许可证；本期检索时为 41 stars。
- **项目：**[joeseesun/qiaomu-codex-imagegen](https://github.com/joeseesun/qiaomu-codex-imagegen)。
- **项目自述：**仓库提供 MCP 服务、命令行和 Agent Skill，README 称可通过它们调用 Codex 内置生图能力；工作流先给出至少四种风格方向，用户选择后再组合提示词、生成图片和 JSON 记录，并按验收条件检查结果。
- **为什么值得关注：**多 Agent 或团队使用图像工具时，难点常在于“谁决定风格、按什么条件验收、如何复现”。该项目将这些节点显式化，值得作为创作型 Agent 的交互与审计设计参考。
- **边界说明：**该仓库关于支持客户端、模板数量、实际生图能力与质量的描述均来自 README；接入前应核实本地 Codex 登录/权限、MCP 配置、模型可用性和第三方素材的许可，勿将示例中的品牌或人物文字用于真实宣称。

## 论文 / 研究

### ScopeGuard：以本地靶场试验间接提示注入对 Agent 安全边界的影响

- **首次公开：**GitHub API 显示仓库创建于 **2026-10-04 07:19 UTC**；仓库未声明许可证。
- **材料：**[Sakshamm-Thakurr/scopeguard](https://github.com/Sakshamm-Thakurr/scopeguard)。
- **项目自述：**该项目让工具调用型 LLM Agent 在本地 OWASP Juice Shop 与 DVWA 靶场中做分诊，并把敌对指令植入 HTTP 响应，比较无防护、非可信内容标记和硬性工具范围限制三种策略。README 提供了提交日志生成的统计表与复现命令。
- **为什么值得关注：**它不仅报告“越权工具调用是否发生”，还记录“规划器是否被误导”。这一区分很关键：工具层的拒绝规则可降低实际损害，但报告遗漏、错误推理或被诱导的任务规划仍可能存在。
- **研究边界：**作者明确称其为 pilot-scale evaluation：一个模型、两个靶场、27 个静态载荷、单次重复，区间较宽且尝试并不独立；这不是通用安全基准、同行评审论文或对所有 Agent 的结论。仓库也只允许在本地、自有或获授权的系统上测试。

## 趋势 / 编辑简评

三个项目分别作用于创作界面、能力调用与安全评测，但共同指向一个朴素原则：Agent 的输出应该能被人看见、修改、追溯和约束。对实践团队而言，优先级不应只是接入更多模型或工具，而是为关键步骤保留人工确认点、记录输入/输出和权限范围，并用与自身任务相符的测试验证失败模式。
